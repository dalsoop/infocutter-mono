# 0004. 자동화 브리지는 위험 동작만 토큰으로 막는다

- 날짜: 2026-06-13 (이전 저장소 `flutter-app-mono` 커밋 `9f4b35f`)
- 상태: 유효

## 배경

디버그 빌드의 자동화 브리지는 MCP 서버와 로컬 도구가 앱을 조작하는 통로다. 루프백(`127.0.0.1`)에만 bind하지만, 같은 기기의 다른 프로세스나 `fetch`를 남용하는 브라우저 페이지도 닿을 수 있다. 그중 일부 동작은 로그인된 페이지에서 임의 JS를 실행하거나, 페이지 내용을 빼내거나, 저장된 API 키를 덮어쓴다.

## 결정

동작을 두 등급으로 나눈다. 일반 등급은 토큰이 설정되지 않은 앱에서 인증 없이 허용한다. 위험 등급(`page.evalJs`, `ai.config`, `page.screenshot`, `evidence.capture`, 쿠키 조회·설정·삭제, `browser.clearData`)은 앱을 `--dart-define=INFOCUTTER_AUTOMATION_TOKEN`으로 띄운 경우에만 허용하고, 토큰이 없으면 403으로 거부한다. 브리지는 `kDebugMode`에서만 시작한다.

## 검토한 대안

- **모든 동작에 토큰을 요구하는 것**: 로컬 도구로 상태를 읽고 탭을 여는 일상 작업이 번거로워진다는 이유로, 일반 등급은 토큰 없이 열어 두었다(브리지 코드 주석).

## 결과

- 새 동작을 추가할 때마다 위험 등급 여부를 판정해야 한다. 임의 코드 실행, 인증된 페이지 내용 유출, 비밀 덮어쓰기 중 하나라도 해당하면 위험 등급 목록에 넣는다.
- 토큰 없이 띄운 디버그 앱에서는 MCP의 `eval_js`, `screenshot` 도구가 동작하지 않는다.
- release 빌드에는 브리지가 없으므로 이 결정은 디버그 빌드에만 영향을 준다.
